# System Map

Cross-repo view of Blackbuck's product flows. The vertical files (`../verticals/`) cover what a PM needs inside one vertical; this file exists only for what doesn't fit inside one vertical's boundary — repo ownership across verticals, and flows that cross repo boundaries. It's small on purpose (two tables) and is loaded unconditionally in Phase 5, regardless of which verticals a PRD is scoped to.

Staleness policy: a flow file (`flows/<id>.md`) with a `last_verified` date more than 90 days old should be treated as "likely stale, re-verify before relying on it" rather than as settled fact. See `SKILL.md`'s "Cross-repo flows" section for the full policy and code-pointer format.

### "Boss" naming — read carefully

"Boss" shows up in five unrelated-looking places: `bb-supply-fo-android`'s former name, `fms_toll`'s `BossPortalController` (route `/blackbuck-portal/`), a shared `/supplywrapper/boss/fastag/*` API path segment called by **both** `bb-supply-fo-android` and `blackbuck-pro-app`, `boss_help_desk`, and `fms_rmm`'s recovery module (calls a `bosswrapper.url` to execute fleet-owner due deductions). Evidence points to "BOSS"/"Blackbuck Portal" being an internal platform brand for FASTag-issuance and account-deduction backend surface shared across client apps and services — not one single owning app or vertical. Don't assume two "boss"-named things are the same system without checking; several of the citations above are flagged as unconfirmed for exactly this reason.

### Known gaps

- **BB Pro's backend gateways aren't cloned yet**: `salesServiceApi`, `omsWrapper`, and `los` (Loan Origination System — also referenced by `ppi-wallet`'s config as a bucket name, `gcp-sit-finserv-los`) are called by `blackbuck-pro-app` but aren't among the 14 repos. Worth asking the PM whether these have their own repos.
- No repo among the 14 is a dedicated GPS, Sales, or Fuel backend — GPS and Sales evidence comes only from feature modules inside `bb-supply-fo-android` and `blackbuck-pro-app`; Fuel evidence is only a `app.fuel.url` config key `fms_rmm`'s reconciliation module calls, no repo owns it yet.
- **Freight/Load Board and Finserve backends are now doubly confirmed missing**: `fms_rmm`'s reconciliation module calls `app.freight.url` and `app.finserv.url` (likely the same `los` system as above) directly, matching the gaps already flagged from `blackbuck-pro-app`'s indent/brokerage and loans modules — two independent repos now point at the same uncloned services.
- **Rewards is a wholly new, previously-unlisted capability**: `fms_rmm`'s reconciliation module calls an `app.rewards.url` backend not covered by any of the 12 named verticals or any repo in this index. Worth asking the PM whether this belongs to an existing vertical (Sales? Load Board?) or is its own thing.
- `fms-ccs` (the Spring Cloud Config server both `fms-outbound-payment-service` and `fms_rmm` pull config from) isn't cloned — it likely holds config/secrets for multiple repos in this index, not just those two.

## Adding or extending a flow

New row here + a file in `flows/<id>.md` (see `SKILL.md`'s "Cross-repo flows" section for the exact format). Keep this table to one row per flow, ~10 words max in any free-text column except Entities — this file must stay cheap enough to load unconditionally on every PRD. **This is not optional bookkeeping**: if Phase 5's interconnection scan on some PRD found cross-repo facts that aren't captured in any existing flow file, adding or extending one here is how that discovery survives past the one conversation that found it. A live scan that isn't written back here gets redone (or missed) by the next PRD that touches the same entity.
